# 哔哩哔哩激励助手

Bilibili 直播奖励领取桌面工具。支持扫码登录、多个账号档案、多个独立领取任务、定时启动和领取结果记录。

## 快速开始

从源码运行需要 Python 3.10 或更新版本（建议 Python 3.12）：

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python app.py
```

1. 打开程序，点击「登录当前账号」。按提示用 B 站 App 扫码并在手机确认。此操作只验证登录，不提交领取。
2. 添加领取任务，粘贴 B 站奖励兑换页面中带有 `task_id` 的链接。
3. 点击任务「设置」调整参数；点击「运行」只执行该任务，点击「全部开始」执行已勾选的任务。
4. 查看任务状态和运行日志。配置会自动保存；也可以导出 JSON 备份或保存参数模板。

参数模板可在任务设置顶部套用、保存或通过「删模板」选择删除。删除只影响当前账号的模板列表，不会修改已套用模板的任务参数。

## 功能

- **任务管理：** 每条任务有独立名称、链接、启用状态和运行参数。支持单条运行、批量启动、日志筛选、参数模板以及配置导入和导出。
- **账号档案：** 首次登录会使用默认账号档案；也可添加多个账号并在空闲时切换。每次只使用当前账号，档案之间分别保存 Cookie、任务和日志。
- **执行控制：** 可按尝试次数、执行时长或持续运行；支持暂停、取消、请求超时、全局最小请求间隔和可选随机抖动。
- **定时执行：** 按北京时间安排首发。默认时刻为下一次 00:00:00，首发延迟为 20 ms。定时模式会使用 NTP 校时，默认服务器为 `ntp.aliyun.com`。
- **串行保护：** 默认一次只发送一个领取请求，并逐条处理任务。请求并发和多链接并发为实验选项，默认关闭。
- **风控处理：** 检测到 HTTP 412/429、常见风控错误码或 IP 异常提示时，停止当前批次后续领取请求。此保护始终开启。

## 参数与行为

默认执行方式是按次数，最多 60 次；单次请求超时 10 秒，任务间隔和账号全局最小间隔均为 1000 ms。实际间隔取二者较大值。次数包含第一次提交。

随机抖动默认关闭，开启后会在失败重试前增加 0 到设定上限的随机等待，不缩短基础间隔，也不影响定时首发。它只改变请求间隔，不能保证避免风控。

B 站返回 `202032`（无资格领取奖励）时，程序按设置继续重试，因为活动资格可能延迟结算。尝试次数、执行时长和全局间隔仍会限制请求。明确库存耗尽、领取成功、手动取消或风控停止时会结束相应任务。

领取接口返回 `code=0` 即记为成功并停止重复领取。有兑换码时显示兑换码；没有兑换码时提示核对账号到账，兼容直接发放至账号的奖励。

定时模式会先校时，再准备登录状态和任务信息，并在目标时刻发出首个领取请求。默认目标延迟为 20 ms；系统调度、网络和请求准备可能造成偏差，不能保证服务器恰好在目标时刻收到请求。NTP 只调整程序内部时间，不修改 Windows 系统时钟。已有任务和模板中明确保存的首发延迟会保留原值。

定时等待会随目标临近提高检查频率：超过 1 分钟时每 250 ms 检查，最后 1 分钟每 50 ms、最后 10 秒每 10 ms、最后 1 秒每 1 ms；每次等待均不超过剩余时间。NTP 往返测量和校时后的时间推进使用 `perf_counter()`，避免部分 Windows/Python 版本的低分辨率 `monotonic()` 影响定时判断。最后阶段采用短时休眠，不忙等、不修改系统计时器设置；Windows 建议使用 Python 3.11 或更新版本，以使用其高分辨率休眠实现。这些是请求的等待间隔，不代表保证达到相同的触发精度。日志会记录等待结束时的唤醒偏差，不含请求准备、限流排队与网络耗时。同一时刻的多个任务默认串行，后续任务仍可能被前一任务推迟。

启用并发或缩短间隔可能增加请求频率。Bilibili 没有为本工具公布或保证任何安全频率；请谨慎设置，并遵守 Bilibili 的服务条款。

## 本地数据与隐私

程序数据保存在 `data/`，运行时会在其中保存登录 Cookie、账号信息、任务配置和日志。Cookie 不会写入任务导出文件。

- 默认账号沿用 `data/bilibili_cookie.json`。
- 新增账号保存在 `data/accounts/<账号ID>/`。
- 任务和日志保存在对应账号档案中。
- 默认账号日志为 `data/logs/claim_live_reward.log`；新增账号日志为 `data/accounts/<账号ID>/logs/claim_live_reward.log`。日志达到 1 MiB 后轮转，保留 `.1`、`.2`、`.3` 三份备份。成功但未返回兑换码时记录响应结构，不记录完整原始响应。

请勿公开分享 `data/`、日志或含真实账号信息的截图。源码运行时数据目录位于项目目录；打包运行时位于可执行文件旁。
